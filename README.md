# 🎸 Chinook API

Современный REST API для управления базой данных музыкального магазина **Chinook**. 
Проект построен на принципах **Clean Architecture** с использованием быстрого **Dapper** для работы с базой данных, без применения тяжелых ORM.

## 🛠 Стек технологий

- **Backend:** C# / .NET 10
- **База данных:** PostgreSQL 17 (с расширением `pgvector`)
- **Data Access:** Dapper (Micro-ORM) + Npgsql
- **Контейнеризация:** Docker & Docker Compose
- **API Тестирование:** Bruno (коллекция хранится прямо в репозитории)

## 🏗 Архитектура

Проект разделен на 4 слоя согласно принципам Clean Architecture:
- **`Chinook.Domain`** — бизнес-сущности (Entities). Не имеет внешних зависимостей.
- **`Chinook.Application`** — интерфейсы и контракты (Interfaces).
- **`Chinook.Infrastructure`** — реализации (Repositories, Dapper, Npgsql).
- **`Chinook.API`** — точка входа, контроллеры, DI-конфигурация.

## 🌟 Ключевые особенности

- 🛡️ **Defense in Depth (Глубокая защита)**: Целостность данных гарантируется на уровне БД (UNIQUE constraints, FK с `ON DELETE NO ACTION`). Приложение перехватывает специфичные ошибки PostgreSQL (`23503`, `23505`) и превращает их в понятные клиенту `400 Bad Request` вместо стандартных `500 Internal Server Error`.
- 🔍 **Прозрачное логирование SQL**: Настроен `Npgsql` с `EnableParameterLogging(true)` и интеграцией с `ILoggerFactory` для вывода чистых SQL-запросов и их параметров в консоль в режиме разработки.
- ⚡ **Производительность**: Использование `NpgsqlDataSource` (Singleton) для эффективного управления пулом соединений, строгая параметризация запросов и использование оператора `RETURNING` для оптимизации операций вставки.

## 🚀 Быстрый старт

### 1. Запуск базы данных
Убедитесь, что у вас установлен Docker. Перейдите в папку `Docker` и выполните:
```bash
cd Docker
docker-compose up -d
```
*Это поднимет PostgreSQL 17 и автоматически создаст схему БД из `init.sql`.*

### 2. Запуск API
Откройте решение `Chinook.slnx` в **Visual Studio 2026** и запустите проект `Chinook.API` (F5).
API будет доступен по адресу: `https://localhost:7090` (порт может отличаться, см. `launchSettings.json`).

### 3. Тестирование API
В корне проекта находится папка `BrunoCollection`. Откройте её в приложении [Bruno](https://www.usebruno.com/) для удобного тестирования эндпоинтов. Коллекция регулярно обновляется.

## 📡 Текущие эндпоинты

### Исполнители (Artists)
| Метод | Эндпоинт | Описание |
| :--- | :--- | :--- |
| `GET` | `/api/artists` | Получить список всех исполнителей (поддержка `?sortBy=name`) |
| `GET` | `/api/artists/{id}` | Получить исполнителя по ID |
| `POST` | `/api/artists` | Создать нового исполнителя |
| `PUT` | `/api/artists/{id}` | Обновить данные исполнителя |
| `DELETE` | `/api/artists/{id}` | Удалить исполнителя *(блокируется, если есть привязанные альбомы)* |

### Альбомы (Albums)
| Метод | Эндпоинт | Описание |
| :--- | :--- | :--- |
| `GET` | `/api/albums` | Получить список альбомов (поддержка фильтрации `?artistId={id}`) |
| `GET` | `/api/albums/{id}` | Получить альбом по ID |
| `POST` | `/api/albums` | Создать новый альбом *(с проверкой на дубликаты названия у исполнителя)* |
| `PUT` | `/api/albums/{id}` | Обновить данные альбома |
| `DELETE` | `/api/albums/{id}` | Удалить альбом |

## 📝 Примечания
- Строка подключения для локальной разработки (из Visual Studio) использует `Host=localhost`.
- Для сборки в Docker используется внутренняя сеть (`Host=postgres`).
- Никогда не используйте `docker-compose down -v` без крайней необходимости, это удаляет все данные БД.
